# 本文方法竞争力与正式实验推进计划

本计划服务于论文主线：在统一的柔性制造加工—运输仿真环境中，检验基于关系图与组相对优势的协同调度方法对总完工时间和动态事件适应性的影响。目标是获得更有说服力的竞争结果，同时保持实验公平、可复现和可回溯。

## 一、主线和冻结边界

当前正式结果作为版本 v1 冻结保存。v1 的训练检查点、测试结果、配对统计和论文草稿不被覆盖；任何新训练、奖励、网络或解码策略都使用新的实验标识和新的结果文件。

方法主线保持为：关系图状态表示、工序—机器—运输设备三阶段决策、候选集约束和组相对优势策略更新。只有在完整验证证据支持结构改变后，才讨论方法名称或贡献边界的变化。加入局部搜索、束搜索或专家初始化时，必须单独标为混合方法，不能把新增搜索过程隐含在原方法名称下。

主对比固定为本文方法、HGS 适配实现和 OR-Tools 有限时间基线。早期图策略版本只用于受控消融或附加分析；未完成统一状态、动作、目标和预算适配的外部方法不进入主表。

训练和模型选择只能读取固定划分中的训练集与验证集。测试实例、测试随机种子和测试事件时间线只在协议冻结后使用一次，不参与奖励、超参数、结构或实例筛选。

### 阶段 2：只验证少量有依据的改进

每次只改变一个因素，先在训练集和验证集筛选，使用与 v1 相同的实例、随机种子、轨迹预算和模型选择规则。候选方法必须写明假设、实现改动、验证指标和回退条件。

候选顺序如下：

1. **训练预算与验证选择**：若阶段 1 显示仍在学习，只增加轮数并使用验证集最佳检查点；不改变测试协议。
2. **多候选解码**：在同一策略检查点下采样多个合法动作序列，使用统一的额外决策预算选择完工时间较小的候选。该版本必须单独报告推理开销，不能与单次策略推理混称。
3. **受约束的轻量局部改进**：仅在策略生成完整调度后执行固定预算的局部交换或插入搜索。若采用该方案，方法名称改为“图策略引导的混合调度方法”，并将纯策略版本作为对照。
4. **加工与运输决策的课程或分阶段训练**：只有在日志显示运输阶段是主要瓶颈时才实施，不能凭直觉同时改变奖励和网络结构。

暂不重新开放复合奖励系数搜索。当前状态下界差分奖励已经经过验证集筛选；若重新比较奖励形式，必须作为独立单因素实验，并重新冻结全部超参数。

**候选保留条件**：在未见测试集上，验证集基础场景完工时间相对 v1 改善至少 5%，完成率不下降，且推理时间不超过预设预算的 2 倍。达不到条件的候选只保留为诊断或消融，不进入正式主方法。

当前验证结果：将模型选择指标改为验证集平均 (C_{\max}) 后，五个训练种子的验证集平均完工时间均低于 v1；在原有六个测试实例、五个训练种子和三次配对运行上，基础场景平均改善约 1.92%，动态事件场景平均改善约 3.17%。动态场景的 bootstrap 区间为负，但符号检验未达到显著性，且训练种子 101 的测试结果回退、105 的结果明显改善。因此该候选暂记为“目标对齐候选 v2”，不替换 v1 主结果，也不宣称全面优于基线。

### 阶段 4：预先固定“强竞争力”判断标准

“完全碾压”不作为统计标准。正式实验开始前固定以下判断规则，结果出来后只按规则解释：

- **静态性能**：在至少 3 个数据集族上，本文方法的平均基础场景 (C_{\max}) 比该族最强基线低至少 5%，并且大多数实例的配对差值方向一致。
- **动态性能**：动态事件场景的平均 (C_{\max}) 和相对退化率不高于最强基线；若绝对完工时间更优但退化率更高，分别报告，不能合并成“更稳定”。
- **统计证据**：报告配对 bootstrap 95% 区间和符号检验；结论以实例级配对为基础，同时披露数据族差异和有效样本数。
- **可靠性**：完成率不低于基线，计划事件和实际执行事件一致；错误、超时和未完成样本不从均值中静默删除。
- **效率**：报告决策时间、总运行时间和环境步数。多候选解码或局部搜索造成的额外开销必须计入。

若满足上述条件，正文可写“在本研究覆盖的数据族和事件协议下取得稳定优势”，并列出适用范围；若不满足，正文继续使用“具有竞争力并呈现数据集族相关差异”，不为了增强措辞而改变协议。

## 三、偏离主线的禁止事项

1. 不使用测试结果反向选择奖励、超参数、模型轮次、数据族或事件强度。
2. 不把单次运行、奖励值、决策次数或单个案例图作为算法优越性证据。
3. 不把 HGS 适配实现写成原论文代码直接复现，也不把 OR-Tools 限时结果写成全局最优。
4. 不把新增局部搜索、束搜索或专家初始化隐藏在“本文方法”中。
5. 不混用 v1 冻结结果和新协议结果；所有扩展结果使用独立版本号和独立统计文件。
