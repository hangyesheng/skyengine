# 论文研究问题与研究定位梳理

## 1. 先给结论

本文已经可以形成一个自洽的研究主线。当前最稳妥的定位不是声称“首次提出动态柔性制造调度”或“首次将图神经网络用于调度”，而是：

> 面向包含柔性加工资源、多 AGV 运输资源和动态扰动的制造系统，构建统一的仿真—调度环境，将工序、机器、AGV、作业和工厂路网组织为动态关系图，并研究一种基于图状态和组相对策略优化的在线协同调度方法；以总完工时间 $C_{\max}$ 为唯一主目标，通过 基础场景—动态事件场景 配对实验评价基础调度质量和动态扰动下的性能退化。

这条主线与当前仿真平台、本文方法和已有实验草稿是一致的。

## 2. 文献已经告诉你的事情

现有研究并不是没有研究加工—运输调度，而是不同工作分别覆盖了问题的不同切面：

| 已有研究方向 | 已经覆盖的内容 | 尚未统一覆盖的内容 |
|---|---|---|
| FJSP-AGV 集成调度 | 机器选择、AGV 分配、运输时间和多目标优化 | 动态事件类型、统一图状态和在线重决策并不一致 |
| 动态 FJSP | 新作业到达、机器故障、加工时间变化或订单扰动 | 运输资源和 AGV 路网常未被显式纳入 |
| 图强化学习调度 | 工序—机器关系、异构图、图策略学习 | 很多工作不包含 AGV、路网和动态故障 |
| MARL/QMIX/PPO/DQN 调度 | 多智能体决策或动态调度策略 | 算法、动作组织和评价协议差异较大 |
| 数字孪生与仿真 | 状态采集、事件注入、调度闭环和过程验证 | 不一定提供统一的加工—运输联合动作和可复现实验协议 |
| AGV/物流控制 | 路网、路径、资源共享、动作掩码 | 往往不同时处理加工工序和机器候选分配 |

因此，本文可以提出的是一个“统一建模与统一验证”的研究问题，而不是把每个组成元素都包装成全新的理论发明。

## 3. 最核心的研究空白

建议把研究空白收束为以下三层，而不是罗列十几个零散空白。

### 3.1 问题建模空白：加工与物流没有被统一成一个动态决策对象

已有研究分别讨论了 FJSP、AGV 调度、动态事件和路网运输，但在不同文献中，机器分配、工序排序和 AGV 选择常常采用不同模型，运输有时只是加工调度之后的执行过程。对于本文所研究的系统，需要在同一个环境中同时处理：

- 多作业和多工序的工艺约束；
- 同一工序的多候选机器；
- 多 AGV 的可用性、位置和任务竞争；
- 机器与路网节点的空间关系；
- 运输、装卸和加工的连续时间推进；
- 事件发生后可行动作集合的变化。

由此形成第一个可辩护的问题：**如何在一个统一状态和动作框架中表达加工资源与物流资源的耦合决策？**

### 3.2 动态适应空白：动态事件没有被统一放入同一在线重决策机制

文献中的动态性定义并不统一。有的只研究随机新作业到达，有的只研究机器故障，有的只研究 AGV 故障或运输变化。因此，不能声称已有研究完全没有处理动态事件；更准确的说法是：**不同事件类型及其对加工—运输协同的影响，缺少统一、可复现的在线重决策评价框架。**

本文的可研究问题是：**当机器故障、AGV 故障和 JOB_ADD 改变当前系统状态时，基于当前状态图的策略能否重新生成可执行的工序—机器—AGV 决策，并控制 $C_{\max}$ 的增加？**

### 3.3 评价空白：基础性能与扰动退化没有被配对分析

许多调度工作主要报告某一组实例上的 makespan 或相对差距，但不同数据集、机器数量、运输资源、事件机制和终止条件之间不能直接横向排名。本文可以形成的评价贡献是：

- 在同一基础实例上构造 基础场景—动态事件场景 配对场景；
- 报告两个场景下的绝对 $C_{\max}$；
- 计算 $\Delta C_{\max}$ 和 $D_{C_{\max}}$；
- 同时报告完成率、timeout/error、实际事件暴露和决策时间；
- 区分基础调度能力与动态扰动适应能力。

因此，本文不是只问“谁的 makespan 最小”，而是同时问：**策略在正常状态下是否有效，以及系统状态变化后性能如何退化。**

## 4. 本文最终应回答的总问题

建议论文第 1 章把总研究问题写成：

> 在包含多作业、多工序、多候选机器、多 AGV 和工厂路网的柔性制造系统中，如何构建能够反映加工—运输关系及动态事件状态的图表示，并据此实现工序、机器和 AGV 的在线协同决策，使系统在以 $C_{\max}$ 为主目标的同时，能够在机器故障、AGV 故障和新作业到达等扰动下保持较小的性能退化？

这个问题与当前实现的对应关系如下：

| 研究问题中的概念 | 当前实现对应物 |
|---|---|
| 柔性制造系统 | 本文仿真—调度环境 |
| 多作业、多工序、多候选机器 | Job、Operation、Machine 和候选加工时间配置 |
| 多 AGV 与运输 | AGV 任务队列、装卸、路径移动和机器转移 |
| 工厂路网 | Point、Link、Graph 和最短路径查询 |
| 动态关系图 | FactoryGraphBuilder、Machine/Operation/AGV/Job 节点及关系边 |
| 在线协同决策 | READY 工序—机器—AGV 三阶段动作生成 |
| 动态扰动 | 事件队列、机器故障、AGV 故障、新作业到达 |
| 主优化目标 | $C_{\max}=env\_timeline$，前提是正常完成 |
| 动态适应性 | 基础场景—动态事件场景 配对、$\Delta C_{\max}$、$D_{C_{\max}}$ |
| 策略优化 | 当前实现的 transition 分组组相对优势 clipped 更新 |

## 5. 方法贡献应该怎样写

建议最终只保留三项主要贡献，避免把工程细节写成过多贡献。

### 贡献一：统一的加工—运输协同仿真—调度环境

构建面向数字孪生验证的仿真—调度平台，在统一执行逻辑下表示作业、工序、机器、AGV 和工厂路网，支持动作执行、连续时间推进、事件注入、状态记录和多算法接入。该贡献的重点是可执行性和可复现性，不应夸大为物理产线数字孪生。

### 贡献二：面向加工—物流协同的动态图状态与分阶段动作

将机器、工序、AGV 和作业组织为动态关系图，并利用工序—机器能力关系、作业—工序关系、工艺先后关系及 AGV—机器可达关系构造当前状态表示。在决策层采用“工序排序—机器选择—AGV 选择”的分阶段动作，减少无效联合动作并保证基本可执行性。

这里应准确写成“图状态编码与分阶段策略决策”，不要声称这是第一个图调度方法，也不要把 AGV—机器可达边写成完整的路径冲突模型。当前实现没有把所有路径长度和冲突细节显式编码进边特征。

### 贡献三：面向动态扰动的统一评价与组相对策略优化实现

在当前方法中采用基于决策转移分组的组相对优势裁剪更新，并在统一仿真环境中使用基础场景—动态事件场景配对评价 $C_{\max}$ 和性能退化。这里必须加限定：当前实现是“基于组相对优势的策略优化实现”，不直接声称等同于原始 GRPO 的同初始状态多轨迹采样机制。

## 6. 论文假设与研究边界

这些边界应主动写清楚，否则答辩时容易被追问。

- 本文研究的是仿真环境中的在线调度，不是现场产线部署验证。
- 本文主目标只有 $C_{\max}$；机器利用率、AGV 活跃率、队列长度等属于奖励塑形或辅助分析量。
- 外部文献中的 makespan 不与本文结果直接横向排名。
- 当前事件是预生成外生事件时间线，不等同于真实生产现场的概率模型。
- 动态事件场景中若包含 JOB_ADD，新增工作量会改变问题规模，必须与纯故障场景区分解释。
- 未来事件不会提前提供给 Agent；Agent 只能访问当前及历史状态。
- AGV—机器图边表示当前可达关系，不等同于完整的交通冲突、死锁和多车路径规划模型。
- 正文不把实现标识当作算法名称；算法理论定位写成“基于关系图与组相对优势的加工—物流协同调度方法”，并说明其为组相对优势策略优化实现，而不是未经证明的严格原始 GRPO。

## 7. 目前真正还缺什么

### 7.1 必须补齐，否则论文无法闭环

1. **把研究主张写成可检验假设。**
   - 在相同基础场景测试实例上，图状态与三阶段协同决策应产生可测量的 $C_{\max}$ 差异，差异方向由正式实验决定。
   - 在相同动态事件时间线上，本文方法的绝对 $C_{\max}$、完成率和 $D_{C_{\max}}$ 应能够被稳定测量，并与主对比方法形成可解释的配对结果。
   - 去除图状态、三阶段决策或组相对更新后，性能变化应通过受控消融观察，而不是凭设计直觉宣称有效。

2. **确定训练、验证、测试实例清单。**
   当前第 5 章仍有实例数量、规模范围和数据划分占位符。必须固定划分并保存配置，防止测试集调参。

3. **确认事件文件和终止逻辑。**
   需要确认机器故障、AGV 故障、混合事件和新作业到达场景的事件文件是否存在；还要确认新作业到达前环境不会因初始作业完成提前终止。

4. **补齐真实运行结果。**
   至少需要基础场景、混合动态事件、机器故障、AGV 故障和新作业到达功能案例。所有运行必须保留完成、超时和异常状态，不能只填成功结果。

5. **完成最小消融矩阵。**
   最少保留：完整方法、No Graph、No Stage Decomposition、PPO/普通 clipped 更新替代组相对更新。若无法可靠实现某个消融，应删去相应结论，不要用概念性描述代替实验。

6. **确认对比方法能在同一环境正常完成。**
   OR-Tools、HGS 适配实现和本文方法需要逐个通过初始化、状态重置、动作执行和正常终止检查。早期图策略实现不能因为存在代码名称就被写成有效主基线。

7. **冻结模型选择规则和随机性记录。**
   当前 benchmark 尚未把 seed 集合明确传入环境 reset。正式实验至少要记录训练初始化、推理采样和事件生成的随机性来源；运行编号不能直接写成随机种子。

### 7.2 可以后补，不影响主线成立

- 完整核验所有 30 条唯一文献的 DOI 和全文方法字段；
- 更复杂的路径冲突、死锁和多车协同机制；
- 更多事件强度和更多数据集族；
- 真实产线数据校准；
- 更严格的原始 GRPO 多轨迹采样实现；
- 大规模泛化和跨地图迁移实验。

这些属于扩展或增强项，不应阻塞当前论文主线。

## 8. 章节填充路线

### 第 1 章：提出问题，不急着证明算法优越

需要填：

1. 柔性制造中加工和运输耦合带来的系统级完工时间问题；
2. 动态事件导致静态计划失效；
3. 现有研究按不同方向分别处理，缺少统一问题和统一评价；
4. 本文总问题、三个子问题和三项贡献；
5. 研究范围和边界。

第 1 章暂时不要写：GraphGRPO 已优于 PPO、QMIX 或 NSGA-II。

### 第 2 章：按四条主线综述并落到空白

按以下顺序组织即可：

1. 数字孪生与制造仿真；
2. 加工—运输协同调度；
3. 动态扰动与在线重调度；
4. 图神经网络和强化学习调度；
5. 文献评述：问题建模、动态机制、图状态、评价协议四个差异；
6. 本文定位。

每一节末尾都要回答“已有研究做到什么、本文还要统一什么”，不要逐篇罗列题目。

### 第 3 章：证明平台能承载问题

重点填平台验证，而不是算法优越：

- 静态加工—运输闭环是否执行；
- 机器故障是否改变机器状态和加工推进；
- AGV 故障是否改变可用 AGV 集合；
- JOB_ADD 是否真的增加作业并被处理；
- 结果文件是否保存完整状态和事件记录。

### 第 4 章：说明方法如何回答总问题

需要特别补齐：

- 图中的每类节点和边分别解决什么信息缺失；
- 三阶段动作为什么比巨大联合动作更可执行；
- 奖励中的塑形项为什么不改变唯一主目标；
- transition 分组更新与标准 PPO、原始 GRPO 的差别；
- 动态事件发生后，图和候选动作如何更新。

### 第 5 章：用实验回答，而不是重复方法描述

核心结果顺序建议固定为：

1. 方法是否能正常完成运行；
2. 基础场景下 $C_{\max}$；
3. 动态事件场景下绝对 $C_{\max}$；
4. 基础场景 到 动态事件场景 的 $\Delta C_{\max}$ 和 $D_{C_{\max}}$；
5. 机器故障、AGV 故障和 JOB_ADD 专项；
6. 消融实验；
7. 决策时间和完成率；
8. 失败案例和研究限制。

## 9. 可以直接放进论文的研究定位段落

> 现有柔性制造调度研究分别从柔性作业车间分配、AGV 运输调度、动态扰动响应、图结构表示和强化学习策略等角度开展了大量工作，但不同研究在资源建模、动态事件、动作空间和评价协议方面存在差异。部分研究将 AGV 纳入加工—运输集成调度，部分研究关注机器故障、随机作业到达或其他动态因素，另有研究使用图神经网络表达工序与机器关系。然而，当前检索证据尚未确认有研究在同一可复现实验框架中，同时统一表示多工序柔性加工、多 AGV 运输、工厂路网和多类动态事件，并以基础场景—动态事件场景配对评价系统级完工时间及性能退化。基于此，本文不将研究目标表述为提出全新的调度问题类别，而是面向上述统一建模与评价需求，构建面向数字孪生验证的仿真—调度环境，并研究基于动态图状态和分阶段工序—机器—AGV 决策的组相对策略优化方法。

## 11. 一句话判断

你现在缺的不是“再找一个研究方向”，而是把已经存在的方向收束为一条可验证链条：

> **统一加工—物流动态建模 → 动态图状态 → 工序—机器—AGV 在线协同动作 → 组相对策略优化 → 基础场景—动态事件场景 配对验证 $C_{\max}$ 与性能退化。**

只要实例划分、事件终止逻辑、基线验收、消融和真实运行结果补齐，论文就从“有方法和平台草稿”进入“研究问题闭环可写、可答辩”的状态。
