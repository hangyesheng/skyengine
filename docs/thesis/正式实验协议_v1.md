# 正式实验协议 v1

这份协议用于冻结第一轮可发表实验的实例、随机种子和评价规则。任何正式结果都必须同时保存本协议版本、训练 checkpoint、事件文件清单和 benchmark `experiment_config.json`。

## 数据划分

第一轮选择 brandimarte 和 kacem 两个数据族，按基础实例划分；同一基础实例的基础场景与动态事件场景始终属于同一集合。实现目录中的工程名称只用于证据追踪。

| split | brandimarte | kacem |
|---|---|---|
| train | `mk02`–`mk08` | `k1`, `k2` |
| validation | `mk09`, `mk10` | `k3` |
| test | `mk11`–`mk15` | `k4` |

当前数据目录中没有 `brandimarte/mk01_agv.txt`，因此不把只有事件文件的 `mk01` 纳入实验。测试集不得用于训练、超参数选择或早停；测试阶段只加载 validation 选择的 best checkpoint。

## 方法与训练

第一轮正式主比较包括：

1. 本文方法的冻结默认分组版本；
2. HGS 适配实现；
3. OR-Tools 有限时间求解基线，仅表述为给定时间限制下的可行解或最佳已知解。

本文方法的严格组采样版本用于组语义消融。它与默认分组版本的每轮轨迹数量和样本组织方式不同，因此不在主结果表中与本文方法并列为第二个独立方法。

早期图策略实现保留为受控消融或附加分析，不能单独承担外部论文复现证据。所有学习方法使用相同训练、验证实例、相同训练轮数、相同设备和相同轨迹终止／超时规则；每个正式训练 seed 都保存独立检查点及其 SHA-256。

建议正式训练 seed 为 `101`、`102`、`103`、`104`、`105`；在资源不足时，至少完成 3 个 seed，并在论文中明确说明。当前首轮严格组消融使用 `--strict-group-size 2`，因为它已经形成可验证的同初始实例独立轨迹组；后续消融是否扩大到 4 或 8 条轨迹需在固定计算预算下单独记录。

严格组的回报按仿真决策批次计算折扣；同一状态产生的工序、机器和 AGV 多阶段 transition 共享一个时间步。任何在该语义修正前生成的严格组结果只保留为历史链路证据，不能作为正式消融结论。

## 测试与配对

测试集每个实例运行相同的运行编号和测试 seed 集合。基础场景与动态事件场景必须使用相同基础实例、相同模型检查点、相同测试 seed 和相同超时。首轮动态事件场景使用默认事件目录中对应的预生成事件文件；事件文件缺失的运行标记为无效，不降级为基础场景。

主结果报告：

- `C_max` 均值、标准差、中位数和完成率；
- 基础场景—动态事件场景配对的 `ΔC_max` 与 `D_C_max`；
- 计划事件数、实际执行事件数、成功处理数和实际事件类型；
- 按新作业到达、机器故障、AGV 故障及混合事件分组的结果；
- 平均决策时间、总运行时间和超时/死锁数量。

配对键固定为“方法、数据集族、实例、运行编号和测试 seed”。只有基础场景与动态事件场景两侧都正常完成且具有有效完工时间的样本进入配对退化统计；完成率则单独报告，不能用配对筛选掩盖失败样本。

## 消融顺序

主结果稳定后再运行以下消融，每次只改变一个因素并固定实例、seed 和预算：

1. 可训练图编码器与固定图编码器；
2. 严格组采样 vs 默认决策批次分组；
3. 组相对更新与 PPO 风格更新；
4. 完整图状态 vs 去图/扁平状态；
5. 完整工序—机器—AGV 三阶段与固定 AGV 选择；
6. 目标差分奖励、时间增量代价与复合塑形奖励对照；奖励模式先在验证集冻结，再进入正式测试。

## 结果冻结条件

只有满足以下条件，结果才可以写入论文主表：

- 所有方法使用同一测试实例和事件文件；
- 每个 trial 有明确的 seed、模型路径和模型 SHA-256；
- 动态事件计划数与实际执行记录完整；
- 无法完成的运行保留原始状态和错误原因；
- 汇总结果的均值、标准差、配对样本数与原始运行记录一致；
- 论文表述只覆盖实际完成的实例、方法、seed 和事件场景。
